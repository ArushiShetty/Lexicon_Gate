## ✦ What is Lexicon Gate?

**Lexicon Gate** is an AI-powered research workspace built around one non-negotiable principle:

> **AI should not answer merely because it can generate text. It must only answer when the available evidence objectively supports the claims.**

Lexicon Gate couples **hybrid dense/sparse retrieval, evidence relevance gating, NLI claim verification, multi-round corrective retrieval, contradiction checking, and self-correction** into a robust research intelligence platform. 

Instead of treating large language models as ungrounded sources of truth, Lexicon Gate treats your indexed literature library as the authoritative evidence layer.

## 🚀 Key Features

### 1. 🤖 Evidence-Grounded Ask (Enhanced Self-RAG)
- **Hybrid Retrieval**: Combines semantic embedding similarity with keyword token matching across multi-page academic papers.
- **Evidence Relevance Filtering**: Drops uninformative or noisy chunks before synthesis.
- **NLI-Based Claim Verification**: Sentences generated by the model are decomposed into individual claims and verified against retrieved evidence using natural language inference (Supported, Contradicted, or Unsupported).
- **Corrective Retrieval**: When claims lack sufficient grounding or sources disagree, the engine automatically triggers adaptive retrieval rounds with targeted query expansion.
- **Multi-Paper Synthesis**: Detects cross-paper consensus and genuine conflicts without hallucinating false disagreements.
- **Clickable Citations & Pulse Focus**: In-line citations `[1]`, `[2]` automatically open the Evidence panel and smooth-scroll directly to the highlighted source excerpt.
- **Pipeline Transparency**: Real-time inspection of retrieval rounds, evidence counts, support scores, and gap disclosures.

### 2. ✍️ Write (Academic Paper Studio)
- **Structured Drafting**: Guided section-by-section drafting (Abstract, Introduction, Related Work, Methodology, Experiments, Discussion, Conclusion).
- **IEEE Formatting & Export**: Export your draft directly to Microsoft Word (`.docx`) with standard academic heading hierarchies and citation placeholders.
- **Public Share Links**: Share readable manuscript drafts with peers via unique shareable links.

### 3. 🔎 Find Papers (Literature Discovery)
- **Multi-Source Aggregation**: Search across **arXiv**, **Semantic Scholar**, and **OpenAlex** in a single unified interface.
- **Direct PDF Ingestion**: Directly import open-access papers into your research library with one click.

### 4. 📚 Research Library & Intelligent Chunking
- **Multi-Format Support**: Ingest PDF, DOCX, Markdown, and TXT documents.
- **Academic Structure Awareness**: Automatically extracts paper titles, authors, publication years, and abstract sections while eliminating noisy bibliography boilerplate from retrieval chunks.

### 5. 📊 Compare & Analyze
- **Side-by-Side Comparison**: Analyze methodology, datasets, baseline models, performance metrics, and limitations across multiple library papers in structured comparison tables.

### 6. 👥 Real-Time Collaborators
- **Researcher Profiles**: Generate and use personal Researcher IDs.
- **Workspace Sharing**: Invite collaborators to join projects and edit paper manuscripts in real time.

### 7. 📅 Research Events Explorer
- Discover upcoming international and national conferences, IEEE calls for papers, and research workshops.

## 🔬 System Architecture

```
User Question
     │
     ▼
[Query Analyzer & Router]
     │
     ├─ (Greeting / Meta) ───────────► Direct Response (Zero Retrieval)
     │
     ▼
[Balanced Retrieval Engine]
     │ (Retrieves chunks across all scoped documents)
     ▼
[Evidence Relevance Gate]
     │ (Filters irrelevant context chunks)
     ▼
[Draft Generation]
     │
     ▼
[NLI Claim Verifier]
     │
     ├─ Fully Supported? ────────────► Format Answer + Citations [1][2]
     │
     └─ Unsupported / Gaps Found?
               │
               ▼
     [Corrective Retrieval Round]
               │ (Expands query & fetches targeted chunks)
               ▼
     [Self-Correction & Abstention Engine]
               │
               ▼
     Final Grounded Answer (or explicit refusal with missing evidence disclosure)
```

## 🛠️ Quickstart & Local Setup

### Prerequisites
- **Python**: 3.11 or higher
- **Node.js**: 18.0 or higher
- **Git**

### 1. Clone the Repository
```bash
git clone https://github.com/ArushiShetty/Lexicon_Gate.git
cd Lexicon_Gate
```

### 2. Backend Setup
```bash
# Navigate to backend
cd backend

# Create virtual environment
python -m venv .venv

# Activate virtual environment
# Windows (PowerShell):
.\.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Run the backend API
uvicorn app.main:app --reload --app-dir . --host 127.0.0.1 --port 8000
```
Backend API will be available at `http://127.0.0.1:8000`. Interactive OpenAPI documentation is at `http://127.0.0.1:8000/docs`.

### 3. Frontend Setup
In a new terminal:
```bash
# Navigate to frontend
cd frontend

# Install dependencies
npm install

# Start Vite development server
npm run dev
```
Frontend web application will be live at `http://localhost:5173`.

### 4. Configuration (`.env`)
Create a `.env` file in the root directory (based on `.env.example`):
```env
# Optional external services (system functions locally with default in-memory engines):
OPENAI_API_KEY=your_openai_key
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key
PINECONE_API_KEY=your_pinecone_key
```

## 🚢 Deployment

### Backend (Render / Railway)
- **Environment**: Python 3.11+
- **Root Directory**: `backend`
- **Build Command**: `pip install -r requirements.txt`
- **Start Command**: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`

### Frontend (Vercel / Netlify)
- **Framework Preset**: `Vite`
- **Root Directory**: `frontend`
- **Build Command**: `npm run build`
- **Output Directory**: `dist`
- **Environment Variables**:
  - `VITE_API_BASE_URL`: `https://your-backend-service.onrender.com`
